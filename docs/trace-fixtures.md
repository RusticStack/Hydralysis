# Semantic-trace fixtures (12.3-hydra.6)

Programs with known answers for the trace features of the engine (spec 14.x, 15.x). They are consumed by the other
lanes' acceptance tests; this lane only provides the programs, their expected answers and a smoke test. No tracing code
is involved.

```
python tests/fixtures/build_fixtures.py <build-dir> [--arch x64|x86] [--only NAME[,NAME...]]
python tests/fixtures/make_trace_expected.py          # regenerates tests/fixtures/expected/*.json
python -m unittest tests.test_trace_fixtures          # builds each fixture (MSVC, x64 and x86), runs it, checks the answers
```

`build_fixtures.py` writes `<build-dir>/<arch>/*.exe|dll|map`, `manifest.json` (the original fixtures, including the
extended `vcall_fixture` and `diff1/diff2`) and `trace_manifest.json` (the new programs: sha256 and linker-map
addresses of every `fx_` function and `g_` datum). The new programs are kept out of `manifest.json` so that
`prepare_fixtures.py` does not import their helper DLLs as analysis targets. Builds are reproducible (`/Brepro`), no PDB.

Every program is deterministic in what it prints (`FX key=value` lines), ends on its own (every one arms a watchdog
that exits with code 99) and runs in a few seconds at most (`replica_*` take about 4.5 s, `deadlock` about 2 s with the
default hold). `tests/fixtures/expected/<fixture>.json` states, per fixture: `functions` and `data` (names in the linker
map), `runs` (arguments, exit code, exact stdout, files produced), and `answers` (the events, relations, verdicts and
identities an acceptance test checks a trace or an analysis result against). `tests/fixtures/trace_fixtures.py` loads
them, builds a group and runs an entry; import it from other lanes' tests.

|---|---|---|

| `veh_freeze` | `veh_freeze.exe [--mode=selftest --seconds=]` | 15.1 a vectored handler that suspends all threads on a first-chance access violation |
| `vcall_fixture` (extended) | `vcall_fixture.exe <stop file> <frames>` | 15.4 two overloads write `Store::value`; `Counter::put(long long)` is only reached through vtable slot 1 |
| `replica` | `replica_a.exe <tag> <log>` (owner), `replica_b.exe <tag> <log> [offset]` | 15.5 moving value, 100 ms delay, 2 s outage, owner-only object, 250 ms clock offset |

Environment-dependent results are printed but never asserted: whether `\\.\Beep` can be opened and what its IOCTLs return,
`IsDebuggerPresent`, pointer values and handle numbers. Process IDs cannot be forced to repeat; `interleave` produces two
child process generations and the PID-reuse case is for synthetic events.

`veh_freeze.exe` and `deadlock.exe --mode=suspend-all` really suspend threads: run them only with a timeout. The default
modes of `veh_freeze` never fault; a probe that dereferences the printed `freed_object` must be non-faulting.
